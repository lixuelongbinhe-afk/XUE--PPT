# XUE-大赛PPT

## 启动与恢复
1. 以本文件绝对路径定位技能目录；不要假定当前目录或把安装目录当工作区。
2. 在用户任务目录运行 `python3 <技能目录>/scripts/workflow.py init <任务目录> --formats docx,pdf,pptx`。只填实际需要的格式；不明确先问用户，不默认全套。已存在状态则运行 `refresh`、`show`，不要重新初始化。
3. 读取 [依赖与工具路由](references/dependencies.md)，只检查当前任务涉及的依赖。运行 `preflight.py` 生成本地探测结果，并在工具清单中实际确认 MCP 可用性；文件或二进制存在不等于服务已连通。
4. 读取 [流程与恢复](references/workflow.md)。明确是技术类、创新创业类或混合任务；沿用已有决定。新出现的关键歧义按 grill-me 一次问一个问题并给推荐答案。

## 要求与证据
5. 读取竞赛章程、评分表、格式模板和用户指定版本，建立要求矩阵；记录来源页码、强制项、页数/字数、匿名、引用、截止日期与需要的交付物。冲突先核实，不猜测。
6. 按 [材料读取与研究](references/sources.md) 处理混合材料：论文统一先入 Zotero；本地项目用 repomix-explorer；GitHub 仓库用 GitHub MCP。固定代码版本并保留出处。
7. 按 [事实与写作](references/evidence.md) 建立统一事实台账。先用 Exa 补充政策、市场、竞品、文献，再追问项目实测数据和经历等关键缺口。代码实现不等于测试通过，计划不等于成果。
8. 要求明确且内容方向已确定就继续。存在新的内容取舍时集中确认一次大纲；不要反复确认已明确的决定。

## 按需生成
9. 技术材料突出方法、架构、实现和验证；创业材料增加需求、竞争、商业模式、成本与明确标为假设的预测。混合材料共享数字、术语、版本和引用。
10. DOCX/PDF 按 [交付与核验](references/deliverables.md) 调用 Documents/PDF 插件。竞赛提供的模板和格式优先于工具默认风格。
11. PPT 先按 [Canva 与 PPT 路由](references/presentations.md) 获取风格参考或可用 PPTX 模板，记录选择；自动选 ppt-master，或 slides → html-to-pptx，并用一句话说明理由。不是 Infinite Canvas。
12. 在目标工具要求的用户关口复用已有确认；若不能复用，留待确认并继续独立任务。不得伪造确认，不把“自动推进”解释成跳过授权。

## 检查与结束
13. 核对要求覆盖、事实引用、跨文件一致性、文件结构和最终渲染。打开实际页面图片检查，不能只凭文本提取或脚本退出码宣称视觉通过。
14. 按 [失败处理](references/fallbacks.md) 自动尝试可用替代路线，仍失败就记录并跳过，继续其余可完成步骤；末尾集中说明。不得将未授权操作、破坏性操作或未验证成品包装成成功。
15. 每个节点完成后保存状态、输入/输出哈希与实际检查证据。用 `refresh` 查变更，只重做依赖受影响的节点；内容或输出变化使相关 QA 失效。
16. 输出用户要求的文件及一份简短交付报告：完成项、替代路线、跳过项、未验证项、是否满足提交要求、下一步。缺少强制项时只能称草稿/部分完成。

## 边界
- 默认只读项目；运行项目测试、构建或启动服务前给出命令、目的、写入范围并取得确认。文档生成/转换与隔离的文档脚本检查可在已授权范围执行。
- Zotero 导入只针对本次提交论文，去重并保留原文件；不批量改旧条目、删文献或上传整个资料库。
- 未公开源码、密钥和个人资料不发送到 Exa/Canva。在线设计只使用必要且获准使用的内容。
- 不自动部署、发布、提交参赛、发邮件、推送仓库或付费购买模板。
- 所有项目指标必须保留证据或注明待补充；外部资料不可替代项目实测。

## 示例
“按这份评分表，把 Zotero 中的论文和本地原型整理为技术报告 DOCX/PDF，再制作 8 分钟答辩 PPTX。”
先解析交付要求与证据，补齐研究，复用已确认方向，按需输出；不因为一次 PPT 导出失败而丢弃已完成报告。
