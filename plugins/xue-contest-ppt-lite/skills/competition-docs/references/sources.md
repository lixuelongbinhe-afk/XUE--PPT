# 材料读取与外部研究

## 竞赛要求
章程、评分标准、官方模板和用户补充可同时存在。记录版本、时间和适用赛道；官方附件控制格式，用户决定写作范围，若二者冲突会影响合规就追问。PDF 扫描件先 OCR 并看原页，公式、表格和不确定字符回看图片，不猜数字。要求不清楚时询问输出类型，不能自动全套。

## 论文统一入 Zotero
读取 zotero-cli 技能与 `reference.md`；先验证可达，机器解析输出使用 `--json`，检查 ok。已有条目使用 library_id+item_key 精确定位；新论文先查标题/DOI并核对作者，避免误合并同名条目。

```bash
zotero-cli --json add file --filepath <论文副本绝对路径> --if-exists skip
zotero-cli --json get metadata <ITEM_KEY>
zotero-cli --json outline <ITEM_KEY>
zotero-cli --json read <ITEM_KEY> --start-page 1 --end-page 5
```

按本机 help 核对选项；不要把示例占位符直接执行。导入前计算哈希，在 sources 中记录映射；重试先查询，写入超时后不盲目重复导入。DOCX 若不能全文索引，先用 Documents 将工作副本转换为 PDF，将 PDF 与原稿关系记入来源，再导入；禁止改写原稿或假设 Zotero 原生能读取所有格式。

提取用户论文的方法、贡献、结果、局限、引用。被论文引用的结论是文献结论，不自动归为用户成果。全文不可得时只用已读部分，不能仅凭摘要编造实验。表格、公式和图片依据实际页面核实。

## 本地项目
用 repomix-explorer，输出显式放任务 work/，不污染源代码树。优先现有 Repomix；若需要安装或 npx 下载，遵循宿主权限；失败可改 rg 定向读取，不无限重试安装。

排除 .env、令牌、证书、私钥、客户/个人数据、依赖产物和无关大文件；先检查配置与筛选结果。安全扫描不是泄密保证。打包内容仅本地分析，不上传到 Exa、Canva。大仓库用 --compress 或缩小 include，同时记录排除范围。最终证据回指原文件与行号，不只引用打包 XML 的位置。

记录架构、核心路径、算法、硬件接口、依赖、测试、部署方式和已知限制。读取现有日志可以形成证据；不能因 README 声称或找到测试文件就写“验证通过”。源码默认只读，不自动安装项目依赖、执行构建或启动服务。

## GitHub 仓库
优先 GitHub MCP，读取目录、README、依赖与核心代码；先确定用户选定 ref，解析 commit 并固定后续读取。根 README 不足以代表实现。使用分页/精确路径减少上下文；记录仓库 URL、commit、路径和可验证行号。私有仓库权限不足时不反复请求同一资源。

若 MCP 不足，优先现有本地副本或可用只读工具；仅在无法替代时将来源标 skipped。远程与本地同时提供时检查是否同版本，差异可能是更新而非错误；无法决定哪个为准时问用户，不能无声混合。

## Exa
先搜索，再打开支持核心论点的原页；使用日期、地区、赛道限定。政策优先政府原文，市场数字优先原始报告并记统计口径，竞品功能看实际官方资料，学术结论查原论文。摘要或搜索片段不够时不要作为已核实依据。

记录标题、URL、发布/更新日、访问日、原始摘录、口径、适用范围和支撑 claim。重大矛盾保留双方依据，再判断或追问。不使用“国家级首创”“行业第一”等无法证明的绝对表述。来源过旧或访问失败要降低可信度。

只发送脱敏后的主题和公开关键词；不将用户未公开方案原文或源码作为搜索词。市场规模与财务预测分开：预测必须列出假设和计算式。外部公开实验不能当作本项目测试。
