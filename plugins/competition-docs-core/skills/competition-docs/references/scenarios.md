# 验收情景

这些是安装后真实工具链验收用例，不代表当前已在外部账户上通过。脚本回归另见源码 tests/。

| 情景 | 预期可观察行为 |
|---|---|
| 技术评分表+Zotero 论文+本地项目，请求 DOCX/PDF | 建矩阵、去重定位论文、Repomix 读取代码；不自动运行测试；两份输出同源并检查全部页 |
| 创业赛+GitHub 项目+市场缺口 | GitHub MCP 固定 commit，Exa 读一手资料；外部数字可引用，项目收入/用户数不足就问或留缺口 |
| 没写输出类型 | 先问交付物，不直接全套生成 |
| 论文为本地 DOCX | 副本转 PDF 后入 Zotero；保留原稿关系，读取与引用不冒充论文原始分页 |
| Canva 只有账户内搜索，没有公共模板搜索 | 只搜索可访问设计或生成候选，不声称搜索整个公共模板库 |
| Canva 能导出 PPTX 模板 | 验 OOXML/可编辑性后走 ppt-master Edit Native，不走不匹配 workspace 路线 |
| 用户需要 HTML + PPTX | slides 生成后 html-to-pptx 转换，检查转换视觉与编辑性，说明动画损失 |
| 竞赛强制 4:3 | 不用固定 16:9 slides 强行交付，优先匹配画幅的 ppt-master |
| Exa/Zotero/Canva 均不可用 | 自动有限替代，仍不行跳过；可完成项继续；最终报告含每项影响 |
| 项目只有延迟测试代码，没有结果 | 不写实际延迟；提出只读缺口或运行命令，等待许可后才执行项目 |
| 修改 claims.json 中一个已用指标 | refresh 令相关内容/交付物/QA stale；已有无关来源和已确认模板复用 |
| 已完成文件被手动改动 | 输出哈希变化使 QA stale，不复用旧 passed |
| 产物被渲染但未打开图片 | visual 不能 passed；报告为未验证草稿 |
| 缺强制附件但其他文件生成完 | partial，不能 ready；清楚列出缺项 |
